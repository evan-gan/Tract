# Spline — Project Context

Infinite canvas vector note-taking app for iPad. Every stroke stores full Apple Pencil telemetry (position, pressure, tilt, timing) for future AI features. Target: iPadOS 26+.

## Building (no Xcode GUI required)

```bash
./scripts/build.sh                    # compile / type-check, unsigned
./scripts/test.sh                     # unit + UI tests on an iPad simulator
./scripts/deploy-device.sh            # signed build installed on a connected iPad
xcodegen generate                     # after editing project.yml
```

`Tract.xcodeproj` is generated from `project.yml` and gitignored — never edit it.
Sources are collected by folder, so new `.swift` files in existing folders need no
config change. Signing values live in `Local.xcconfig` (gitignored; copy
`Local.xcconfig.example`). Full details in `.claude/CLAUDE.md`.

---

## Key architectural rules

- `CanvasViewModel` is the single source of truth for all canvas state. Every component reads from it or calls methods on it.
- `CanvasContainerView` is the only view that imports from multiple feature folders. Everything else stays within its own folder.
- `@Observable @MainActor` throughout — no `ObservableObject` or `@Published`.
- Pencil draws; fingers pan/zoom only.

## The tool dock

`FloatingToolDock` is the movable bar holding undo/redo, the tool carousel, stroke
weight, and the quick ink colours. Rules that hold when changing it:

- **Placement is view state.** `parkedEdge` lives in `FloatingToolDock`, not
  `CanvasViewModel`. Keep it there: `@State` is what re-lays-out the dock.
- **Snapping is by quadrant, not by distance.** `DockEdge.nearest(to:in:)` splits the
  container on its two diagonals, so the dock commits to the edge the finger is
  heading toward. It is pure and unit-tested — keep it that way.
- **The dock re-flows, it does not rebuild.** `DockLayout.stack(along:)` returns an
  `AnyLayout`, so children keep their identity and slide between row and column.
- **Drag from the grip or any empty part of the bar.** The gesture is on the whole
  dock with a minimum distance, so button taps still work; the grip is the affordance.
- **The canvas must own the whole screen.** It is presented as a `fullScreenCover`,
  not a split-view detail column — a sidebar covers the dock in portrait and
  swallows drags aimed at it.
- The colour rail rings a swatch only while a drawing tool is active
  (`CanvasViewModel.selectedInkColor` is nil otherwise), and picking a colour while
  erasing hands back to the last pen used.

## Liquid Glass chrome

All floating controls use Liquid Glass (iOS 26). Rules that must hold when adding chrome:

- Glass is for the **navigation layer only** — never the canvas, strokes, or selection box.
- Every chrome surface goes through `.glassChrome(cornerRadius:isInteractive:)`; do not call
  `.glassEffect` directly, and never put a material background on chrome.
- **No glass inside glass.** A control on an existing glass surface shows state with an accent
  tint (see `ToolButton`), not a second glass layer. A panel that needs its own surface becomes
  a *sibling* of the palette, as the color panel and weight flyout do.
- All chrome lives in the single `GlassEffectContainer` in `CanvasContainerView.overlayChrome`
  and carries a unique `.glassEffectID(_:in: glassNamespace)`, so surfaces morph into one
  another and share one backdrop layer.
- Toggle panel visibility through `CanvasViewModel.toggleColorPanel()` /
  `toggleStrokeWeightFlyout()` — they wrap the change in `withAnimation`, which is what drives
  the morph, and they enforce one-open-at-a-time.
- Sheets get their glass from the system: keep a partial-height `.presentationDetents`, never
  add `.presentationBackground`.

## Core Data schema

| Entity | Key fields |
|---|---|
| `DocumentEntity` | id, title, createdAt, modifiedAt, canvasOriginX/Y, canvasScale, → strokes (to-many) |
| `StrokeEntity` | id, sessionID, startTime, endTime, colorR/G/B/A, lineWidth, opacity, tool, pointsData (JSON-encoded `[StrokePoint]`), → document |

Points are stored as binary JSON, not individual entities — a stroke can have thousands of points.

---

## Input pipeline

```
Apple Pencil → UIView.touchesBegan/Moved/Ended
  → guard touch.type == .pencil
  → coalescedTouches(for:)  ← captures all 240 Hz samples
  → StrokePoint (screen → canvas via CanvasTransform.toCanvas)
  → CanvasViewModel.beginStroke / continueStroke / endStroke
  → SwiftUI Canvas re-renders
```

## Where to make common changes

| Change | File |
|---|---|
| Add a new tool | `ToolType` in `StrokeStyle.swift` (icon + `isDrawingTool` live there); the dock picks it up automatically |
| Change the dock's quick colours | `InkColor.dockPalette` in `InkColor.swift` |
| Change how the dock snaps | `DockEdge.nearest(to:in:)` in `DockEdge.swift` |
| Change canvas background | `CanvasBackgroundView` in `CanvasContainerView.swift` |
| Add a new export format | New `*Exporter.swift` conforming to `ExportAdapter`, add to `ExportSheetView.adapters` |
| Change the glass chrome style | `View+GlassChrome.swift` |
| Change preset colors | `presetColors` array in `ColorPresetGrid.swift` |
| Change stroke smoothing | `CanvasRenderer.buildPath(for:)` |
| Swap renderer for Metal | Replace `CanvasRenderer.swift` with an `MTKView` wrapper — data model unchanged |
| Add AI feature | Read from `Stroke.points` (telemetry), `startTime`/`endTime`, `sessionID` |
